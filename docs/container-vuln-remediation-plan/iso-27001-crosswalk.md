# ISO/IEC 27001:2022 (Annex A) Crosswalk — Container Vulnerability Management

> Sanitized reference crosswalk. Maps container VM program activities to ISO/IEC 27001:2022 Annex A controls.

| Program activity | Annex A control | Control name |
| --- | --- | --- |
| Vulnerability scanning & flaw remediation | **A.8.8** | Management of technical vulnerabilities |
| Configuration management / hardening | **A.8.9** | Configuration management |
| Runtime / malware protection | **A.8.7** | Protection against malware |
| Secure development lifecycle | **A.8.25** | Secure development life cycle |
| Secure coding / build | **A.8.28** | Secure coding |
| Security testing in development | **A.8.29** | Security testing in development and acceptance |
| Separation of dev/test/prod | **A.8.31** | Separation of development, test and production environments |
| Change management (upgrades) | **A.8.32** | Change management |
| Logging & monitoring | **A.8.15 / A.8.16** | Logging / Monitoring activities |
| Capacity & availability (EOL upgrades) | **A.8.6** | Capacity management |
| Information security in supplier/tooling | **A.5.19–A.5.23** | Supplier & cloud service security |
| Threat intelligence (exploitability) | **A.5.7** | Threat intelligence |

## Note on prioritization

The risk-based prioritization model directly supports **A.8.8**, which requires vulnerabilities to be evaluated and addressed based on associated risk — not merely detected. Exploitability + reachability enrichment is the documented "risk" input.
